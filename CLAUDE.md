# Shootcut — project rules

## Keep the Features page current (standing rule)
Whenever a feature is added, changed or removed, update the Features page in the **same change**:

- `src/lib/features.ts` — `TOOL_FEATURES` (one entry per ready tool, Arabic and English, Western digits), `GENERAL_FEATURES`, `NOT_AVAILABLE`.
- `src/lib/shortcuts.ts` — any new or changed keyboard shortcut (the Features page table is generated from it).
- `README.md` — the status table.

`src/lib/features.test.ts` fails if a ready tool has no feature entry.

## Structure
- The home page is a search box (`src/components/ToolSearch.tsx`, matching in `src/lib/search.ts`, both languages) and the five sections: PDF, Images and designs, Video, audio and editing, Documents, sheets and slides, Engineering (`SECTIONS` in `src/lib/tools.ts`), and nothing more: no What-is-new list (new tools get a badge on their own card from `WHATS_NEW`, at most three ids). It must stay that short: the Studios are not on it; each studio has a `section` in `STUDIOS` and is shown as a slim strip at the top of that section's page (`SectionStudios`, above the tools) and in the "Full programs" menu of the tool bar. Each tool belongs to a group, each group to a section; a group holds at most seven ready tools (a test checks it), so split a group before it grows.
- Everything runs in the browser. No server, no uploads, no paid or terms-violating services, no third-party requests.
- Video tools run FFmpeg (WebAssembly) through `src/lib/video/engine.ts`: the 32 MB engine is copied to `public/ffmpeg` by `scripts/copy-assets.mjs` and kept in the browser's Cache Storage after the first download. Command lines are built in `src/lib/video/args.ts` (tested); pages share `src/components/VideoTool.tsx`. WebM uses VP8 because the VP9 encoder crashes in this build. Never add a CDN URL.
- PDF page tools (split, extract/remove, crop, repair) are in `src/lib/ops/pdftools.ts` and `src/tools/PdfPageTools.tsx`.
- Image tools share `src/components/ImageBatch.tsx` (many pictures) or `src/tools/ImageEditTools.tsx` (one picture); the picture maths lives in `src/lib/ops/imgops.ts` with tests.

- The person chooses places, never a fixed preset only: crops use the draggable `src/components/CropFrame.tsx`; watermark and meme text use `PlacePad.tsx` or clicks on the preview; the PDF stamp has its own free placement.
- Files the person adds (PDF, pictures, video) are kept in IndexedDB (`src/lib/persist.ts`, `src/hooks/useKeptMedia.ts`, `MediaKeepBar`) so the next tool opens with them. Nothing is kept until the person chooses yes once; saved files expire after 24 hours; the bar offers delete, delete-all and an off switch.

- Studios (`src/lib/studios.ts`, `src/components/Studios.tsx`): five studios embed open-source web apps (Rust/WebAssembly, MIT OR Apache-2.0) built by `.github/workflows/studios.yml` (matrix must match `STUDIOS`, a test checks it) into the `studios` branch; `deploy.yml` copies that branch into `public/studio`. A page opens at once on the edition that suits the device (Light on phones or without WebGL, else Full), or on the one the person chose last (`shootcut-edition` in localStorage); an always-visible switch at the top moves between Full and Light. Never put a choice screen in front of the content again. Before compiling, `scripts/patch-studio.py` gives each app Shootcut's identity: names, logos and pictures, colours (blue/green/orange become the brand red), no Discord or community links, loading text "Loading Shootcut Program…", favicon, and the `?lang=` language hand-over; every `ctx.set_fonts(..)` in an app's `ui-egui` crate is wrapped by `patch-studio.py` so the interface always has an Arabic face (`scripts/studio-fonts/shootcut_arabic.*`, IBM Plex Sans Arabic, OFL). `patch-studio.py dist` also writes `<app>_bg.wasm.gz` and makes the page load that copy (with a percentage in the loading text; the raw file stays as fallback). The workflow pins each app to a commit (`ref:` in `studios.yml`, the same shas `build.json` records) because the upstream moves and drifts away from the edits; to follow upstream, move the pin and fix the edits together. Every per-app edit must match or the build stops; the build log lists what is left of the old names. Nothing visible may show the upstream's name, logo, colours or Discord. The licence texts stay with each app (legally required) and are listed on the `#/noticesssssshotcuts` page, linked discreetly from the footer. Never use the upstream's names or logos as Shootcut's own branding. Studio names on the home page are plain: Documents, Design, Video editing, Audio, Engineering (المستندات، التصميم، المونتاج، الصوت، الهندسة).

- PDF has two editions: the PDF card (`#/pdf`) opens `StudioPage` for the hidden studio `pdf` (`hidden: true` in `STUDIOS`, so it is not a sixth studio and not in the Studios block): Full = the pdfcraft app (`studio/pdf/pdf`, matrix id `pdf`), Light = the PDF tools (`ToolGrid section="pdf"` passed as `lightContent`). `patch-studio.py` has pdfcraft EDITS (Discord button, home community card, about logo, link tables) and `PDF_LOADING` (a Shootcut loading screen, since its page is a bare canvas).

- The five sections are always visible as tabs under the header (`main-tabs` in `Header`, `src/components/Shell.tsx`) on every page, the current one highlighted: moving to another section never needs a trip back to the home page. Inside a section the tool bar (`ToolNav`) has at most two menus: "Tools" (every group of the section in one panel) and "Full programs" (the section's studios). Section pages (`ToolGrid` in `src/App.tsx`) show the groups as tabs (All + one per group). A group with a single tool is merged into a neighbouring group instead of standing alone (forms into review, convert into optimize, slides into sheets). Tool pages show a breadcrumb chip with their section. Never go back to a row of group buttons.

## Other conventions
- Arabic text in the interface is Modern Standard Arabic (Fusha), not dialect.
- Arabic (RTL) and English (LTR) must both work; add every string to `src/i18n.tsx` in both blocks.
- No third-party network requests. Everything runs in the browser.
- Shortcuts match `KeyboardEvent.code` (layout independent); Ctrl on Windows, Command on Mac.

- Documents studio in Arabic: Docs (wordcraft) gets `ar.tsv` + `bidi.rs` (`scripts/studio-patches/wordcraft/`, registered by EDITS in `i18n/mod.rs`), Sheets (gridcraft) gets `i18n/ar.rs` + `bidi.rs`, Slides (deckcraft) has no i18n so `patch-studio.py` `deck_wrap` routes labels through `ui-egui/src/ar.rs` (table + `t`/`tb`). Catalog sources must equal the patched English text (names are cleaned first). When a pinned sha moves, re-extract the English strings and translate the new ones. The language comes from `?lang=` (page script sets `navigator.language`). Design, Video editing, Audio and Engineering stay English.
